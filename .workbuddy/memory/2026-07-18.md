## 复发修复：不停刷新后后端进程被关闭（17:09–17:30）

### 现象
用户再次报告"不停刷新网页后系统会出现异常"，明确为**后端进程被关闭**。

### 根因（与上次一致，但未生效）

- `backend/app/core/database.py`：WAL 模式（journal_mode=WAL / busy_timeout）。

核查：当前后端连接的 `backend/data/db/order_system.db` 已生成 `-wal`/`-shm`（WAL 已激活），说明"慢"根因已解，但杀进程的旧看门狗还活着。动手前 PID 3392（旧后端）已被旧看门狗杀掉。

### 操作（用户授权"我来重启"）
1. 结束旧进程树：启动器 5880、后端 3392（已死）、前端 4556/13120；释放 8000/5173。
2. 重启：启动器 PID 19320（新看门狗）、后端 PID 5868（uvicorn，WAL）、前端 5173（vite）。
   - 启动器服务需手动点"启动"按钮拉起（不自动启动），故后端/前端由我直接拉起。
3. 验证：/health 返回 healthy；WAL 文件时间戳更新；压测 8×60=480 并发请求 0 错误，最终 /health 仍 healthy，后端 PID 5868 未被看门狗重启。

### 结论
WAL 消除"慢"，新看门狗消除"误杀"。本次启动器已用新代码运行，复发问题已解决。
注意：启动器本身不自动启动服务，重启后需在前端/后端按钮上点"启动"（本次已手动拉起）。

## 修复：编辑订单改收货地址后地图不更新（17:42–17:50）

### 背景
智慧大屏地图按订单 `receiver_address` 识别国家（`/api/dashboard/country-distribution`），且只在 `detected_country IS NULL` 时重新识别。原 `update_order` 保存时**完全不碰 `detected_country`** → 已识别过国家的旧订单，改地址后地图仍显示旧国家，不更新（bug）。

### 改动（backend/app/api/orders.py）
- 第 506 行前：记录 `old_receiver_address = order.receiver_address`。
- 第 519 行 `await db.commit()` 前：若 `receiver_address` 在 update_data 且新值≠旧值，则 `order.detected_country = None` 并记 changes。
- 效果：保存改地址时重置国家识别，下次 boss 大屏刷新（≤3 分钟，缓存 150s 过期）自动按新地址重新识别，地图更新。
- 发货端 `receiver_address` 为 disabled，不会触发（allowed_fields 不含它），符合预期。

### 验证
- 前端两处编辑入口（Orders.vue:715、UniversalOrderList.vue:1515）保存均提交 `receiver_address`；`OrderUpdate` schema 含该字段 → 重置逻辑必触发。
- 后端已重启（原 PID 5868 结束，新进程拉起），`/health` 返回 healthy，新逻辑已编译进进程。

## 修复：工资结算"查看明细"点击查询异常（17:50–18:0x）

### 现象
工资结算页（CommissionSettlement.vue，仅 boss）点"查看明细"→ 弹窗查询异常（前端 catch 显示"查询失败"），列表本身正常。

### 根因（实锤）
- `models.py` 第 47/58 行：`sales_amount`、`commission_amount` 均为 **String(20) VARCHAR**。
- 后端 `get_unpaid_orders`（commission_settlement.py:102-103）直接 `round(order.sales_amount or 0, 2)` —— 对字符串调 round 必抛 `TypeError: type str doesn't define __round__ method`（已用 `round('123.45',2)` 实锤）。
- 仅当金额字段非空时触发；列表接口 `get_unpaid_commission` 用了 `func.cast(..., Float)` 故正常 → 解释"列表出、点明细崩"。
- 前端 API 路径 `/commission-settlement/unpaid/orders` 正确，非路径问题。

### 改动（backend/app/api/commission_settlement.py）
- 模块顶部新增 `_safe_float(value)`：None/空/非法返回 0.0，否则 `float(value)`。
- 第 113-114 行改用 `round(_safe_float(order.sales_amount), 2)` / `round(_safe_float(order.commission_amount), 2)`。
- 同样风险点排查：`get_unpaid_commission` 用 SQL 层 cast 已正确；`get_unpaid_orders` 是唯一遗漏点。

### 验证
- `round('123.45',2)` 实锤抛 TypeError（根因确认）。
- `_safe_float` 边界测试：`'123.45'→123.45`、`None→0.0`、`''→0.0`、`'abc'→0.0`、`' 99.5 '→99.5` 均安全。
- 后端已重启（原 PID 20820 结束，新进程拉起），`/health` 返回 healthy，修复已编译进进程。
