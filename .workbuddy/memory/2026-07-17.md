
## 诊断+修复：登录后不停刷新导致后端异常（约 09:xx）
### 根因
- 后端 SQLite 未开启 WAL 模式（默认 rollback journal）。多进程/高并发访问同一 db 文件会互相加锁，刷新时的写操作（如登录写 OperationLog）与并发读争用，导致请求变慢甚至 database is locked。
- 后端变慢 → 启动器看门狗的 /health 探测偶发超时 → 旧看门狗累计失败 4 次（约 60s）即强杀后端进程并重启 → 在途连接被 TCP RST（客户端见到 ConnectionResetError/10054，即用户说的"后端异常"）。
- 隔离端口 8005（无看门狗）压测 480 并发只读 + 240 取消连接：0 错误，证明后端逻辑本身稳，杀手是看门狗在刷新风暴下误杀。

### 修复
1. backend/app/core/database.py：engine 增加 connect 监听器，每连接执行 PRAGMA journal_mode=WAL / busy_timeout=5000 / synchronous=NORMAL。消除锁竞争，允许多读+单写并发。
2. 启动器.py `_health_watchdog`：改为"仅当 8000 端口彻底不通（连接被拒）才重启"；对只是繁忙（/health 偶发超时）只告警、绝不误杀；仅当端口在监听且 /health 连续失败约 3 分钟（12×15s）才判真死锁重启。阈值大幅提高，刷新风暴不再触发。

### 验证
- 用新代码在 8005 启动：健康，WAL 文件(-wal/-shm)生成。
- 在 8000 用新代码(WAL)拉起后端，压测 160 并发请求(10 轮刷新)：0 异常、/health 全程在线、无 ConnectionReset（之前 1m22s 还崩）。
- 临时压测脚本 repro_test.py/repro_test2.py/repro_abort.py/repro_verify.py 均已清理。

### 生效说明
- WAL 已对当前运行的 8000 后端生效（已手动用新代码拉起稳定后端）。
- 看门狗新逻辑在 启动器.py 文件内，需**重启启动器(关闭并重新打开 启动器.py)** 才激活；但 WAL 已让后端不再变慢，旧看门狗也不会再误杀。

## 修复：智慧大屏打不开（10:10–10:14）
### 现象
1001 账号（boss 角色）登录后点击"智慧大屏"菜单，页面白屏，Vite 报错覆盖层显示编译错误。

### 根因
`OrderDetailDialog.vue` 第 23–52 行：在 `<template>` 内部的 `<div>` 中嵌套了 `<style>` 标签（定义 .detail-info-row / .detail-label / .detail-value 等样式）。
Vue SFC 规范要求 `<script>` 和 `<style>` 必须是顶层标签（与 `<template>` 平级），不能放在模板内部。Vite 编译器检测到后抛出 `createCompilerError: Tags with side effect (<script> and <style>) are ignored in client component templates`。
`SmartDashboard.vue` 引用了 `OrderDetailDialog.vue` → 该组件编译失败 → 智慧大屏整个白屏。

### 修复
1. 删除 `OrderDetailDialog.vue` 模板内部的 `<style>...</style>` 块（原第 23–52 行）。
2. 将其中 4 条 CSS 规则（.detail-info-row / .detail-label / .detail-label::after / .detail-value）移入文件底部已有的 `<style scoped>` 块中，保持样式效果不变。
3. 前端 dev server（5173）正在运行，Vite HMR 自动热更新生效。
