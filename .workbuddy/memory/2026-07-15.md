经过全面排查，发现 **3 层问题叠加** 导致故障：

2. **`verify_password()` 无异常保护**
   - 密码哈希中 `hashed_password.split('$')` 在格式异常时抛出 ValueError → 导致 500
   - 修复：添加 try/except，对无效格式返回 False 而非崩溃
   - 增加了 salt/hash 空值校验

3. **启动器依赖检查不完整**
   - 旧代码只检查 `import fastapi`
   - 修复：扩展为检查 8 项关键依赖（fastapi, uvicorn, sqlalchemy, aiosqlite, jose, passlib, multipart, pydantic）

## 修复后端卡死问题（15:34）

### 诊断
用户反馈：启动器刷新状态显示"端口已占用但无响应"，过一会网页就无响应了。
TCP 连接端口 8000 成功但 HTTP 请求超时 → 异步事件循环卡死（deadlocked）。

根因链：
1. `get_orders` 每次查订单列表都遍历所有订单写入 `order_days` → 读接口做了写操作
2. SQLite 只允许 1 个写者 → 多个并发请求同时写 → 写锁排队
3. 数据库连接池 `pool_size=20` + `pool_use_lifo=True` → 大量连接涌入抢写锁
4. 全部连接卡在等待 SQLite 写锁 → 事件循环停摆 → 新请求（包括 /health）全部无法处理

### 修复
1. **移除 `get_orders` 中的写入操作** — `order_days` 仅在 create/update 时设置，不在查询时更新
2. **优化连接池配置** — pool_size 20→5, max_overflow 30→10, 移除 pool_use_lifo, SQLite 添加 timeout=30
3. **统一调度器会话管理** — scheduled_log_cleanup 改用项目统一的 AsyncSessionLocal

### 修改文件
- `backend/app/api/orders.py` — 移除 get_orders 中的写库操作（第263-268行）
- `backend/app/core/database.py` — 连接池配置优化
- `backend/app/services/scheduler.py` — 统一使用 AsyncSessionLocal

### ⚠️ 关键排查经验：端口被孤儿 uvicorn 抢占导致"改了代码但不生效"
现象：磁盘 dashboard.py 已含新字段，但接口一直返回旧结构；加 `_marker` 调试字段也不出现。最终定位：
1. 本会话前几轮用 Bash 后台启动的 uvicorn（bi7wTY，reloader 2916 + server 12840）和启动器(启动器.py=8044)启动的后端(18140 + 17504)在端口 8000 上并存；`taskkill` 杀掉 reloader 后，其 server 子进程(12840)以孤儿身份存活并继续在 0.0.0.0:8000 提供**旧代码**
2. uvicorn 默认 `SO_REUSEADDR`，多个进程可同时绑 0.0.0.0:8000，内核把连接随机分给新旧进程，导致现象时好时坏、调试标记不出现
3. 解决：用 `wmic`/`Get-CimInstance Win32_Process` 列出所有 python 进程及父子关系，逐个 `taskkill /PID <server_pid> /F` 清掉所有旧 server 孤儿进程（12840、17504），仅保留一个全新 `uvicorn --reload`(NwxU1T) 后端，新代码才生效
4. 注意：`netstat -ano` 在 Windows 上对刚杀掉的进程会残留 LISTENING 条目（wmic 显示"无可用实例"），以 wmic/CIM 为准判断进程是否真死
5. 启动器(8044)本身不要随意 `taskkill /T /F` 杀树——会被权限拦截且会中断用户系统；只杀孤立的 server 子进程即可

1. **混合方案**：离线先扩展多语言国名词典（日/韩/法/德/俄/西/阿/意/葡/泰/越等常用国名），识别不到的地址再用联网翻译兜底
2. **自动联网搜索兜底**：翻译后仍识别不出，再用免费搜索接口（DuckDuckGo）搜地址所属国家
3. **持久化到数据库**：给 orders 表加 `detected_country` 字段，首次算完存库，刷新直接读；地址未变不重复联网
4. **搜索服务用免费接口**：零配置，不稳定/失败时自动降级为丢弃，不影响主流程

### 后端改动 `backend/app/api/dashboard.py`
